# 官方小智加自建服务实施方案

## 1. 目标

本方案的目标是：继续使用官方小智服务器负责语音对话能力，同时自己另外部署一个轻量 Home Server，用来承载 StackChan 的扩展能力。

扩展能力包括：

- Telegram 或其他即时通讯接入。
- 远程查询机器人状态。
- 远程让机器人说话或显示消息。
- 拍照、保存图片、发送到 Telegram。
- 基础视觉问答。
- 家电控制。
- 后续录像、异步任务、任务状态查询。

当前阶段不优先做：

- 自建完整小智服务端。
- 替换官方小智语音链路。
- 依赖 `xiaozhi.secret_key`。
- 直接接 Codex 或 Claude Code。
- 复杂多用户权限系统。

## 2. 总体架构

整体拆成三部分：

```text
官方小智服务器
负责：语音识别、对话理解、TTS、Agent、决定是否调用 MCP 工具

StackChan firmware
负责：注册 MCP 工具、本地执行动作、拍照、访问 Home Server

自建 Home Server
负责：Telegram、远程命令、图片/视频保存、视觉模型、家电控制、状态管理
```

也就是说，不把所有能力都塞进 firmware，也不一开始自建完整小智后端。

推荐路线是：

```text
继续用官方小智做语音大脑
自己写 Home Server 做扩展能力
firmware 通过 MCP 把两边接起来
```

## 3. MCP 调用关系

MCP 工具注册在机器人 firmware 里，但调用决策通常来自官方小智服务器。

调用链路如下：

```text
用户说话
-> 机器人麦克风采集音频
-> 官方小智服务器识别和理解
-> 小智决定调用某个 MCP 工具
-> 工具调用请求下发到机器人
-> firmware 执行本地 MCP handler
-> firmware 请求 Home Server 或执行本地动作
-> 执行结果返回给小智
-> 小智组织自然语言回复
```

所以可以理解为：

```text
工具列表：机器人提供
调用决策：小智服务器做
动作执行：机器人本地做
业务能力：Home Server 承担
```

## 4. 当前 firmware 可用基础

### 4.1 MCP 注册点

当前 MCP 工具注册位置：

```text
firmware/main/hal/hal_mcp.cpp
```

已有工具包括：

```text
self.robot.get_head_angles
self.robot.set_head_angles
self.robot.set_led_color
self.robot.create_reminder
self.robot.get_reminders
self.robot.stop_reminder
```

后续新增工具也应放在这里。

### 4.2 AI Agent 初始化链路

AI Agent 模式会进入小智运行时，HAL 初始化时会注册 MCP 工具。

核心链路：

```text
app_main()
-> GetHAL().init()
-> Hal::xiaozhi_mcp_init()
-> 打开 AI.AGENT
-> GetHAL().requestXiaozhiStart()
-> Hal::startXiaozhi()
-> hal_bridge::start_xiaozhi_app()
-> Application::Run()
```

因此新增 MCP 工具不依赖 StackChan server，也不依赖 `xiaozhi.secret_key`。

### 4.3 HTTP 能力

firmware 已经有 HTTP 调用模式，可以通过 xiaozhi board network 创建 HTTP client：

```cpp
auto& board = Board::GetInstance();
auto network = board.GetNetwork();
auto http = network->CreateHttp(0);
http->Open("GET", url);
std::string response = http->ReadAll();
```

已有参考文件：

```text
firmware/main/hal/hal_account.cpp
firmware/main/hal/hal_app_center.cpp
firmware/main/hal/board/stackchan_camera.cc
```

新增 MCP 工具访问 Home Server 时，优先复用这个模式。

### 4.4 摄像头基础

当前已有摄像头能力：

```text
StackChanCamera::Capture()
StackChanCamera::Explain(question)
```

`Explain(question)` 已经能把画面编码成 JPEG，并通过 multipart/form-data 上传到指定视觉接口。

当前缺口是：

```text
还没有注册 self.vision.describe_scene 之类的 MCP 工具
还没有在 AI Agent 路径里配置 vision explain URL
```

## 5. 前置准备

### 5.1 拉取 firmware 依赖

当前仓库里的 firmware 依赖源码不是完整展开状态，需要先执行：

```bash
cd /Volumes/ORICO1TB/project/open/StackChan/firmware
python3 ./fetch_repos.py
```

这个脚本会根据 `firmware/repos.json` 拉取：

```text
components/mooncake
components/mooncake_log
components/smooth_ui_toolkit
xiaozhi-esp32
components/ArduinoJson
components/esp-now
```

其中 `xiaozhi-esp32` 是 AI Agent、小智协议、MCP server、HTTP 封装等能力的来源。

### 5.2 准备 ESP-IDF

firmware README 要求 ESP-IDF v5.5.4。

在 build 之前，需要确保当前 shell 能找到：

```bash
idf.py
```

如果找不到，需要先 source ESP-IDF 环境。

### 5.3 配置 Home Server 地址

不建议直接复用现有：

```text
CONFIG_STACKCHAN_SERVER_URL
```

因为它已经被账号、App Center、Avatar WebSocket 等 StackChan 旧逻辑使用。

建议新增独立配置：

```text
CONFIG_HOME_SERVER_URL
```

示例：

```text
http://192.168.1.10:18080
```

后续 MCP 工具统一访问：

```text
{CONFIG_HOME_SERVER_URL}/robot/status
{CONFIG_HOME_SERVER_URL}/vision/explain
{CONFIG_HOME_SERVER_URL}/home/device/control
```

## 6. 第一阶段：跑通最小语音调用链路

第一阶段只做一个状态查询，不做 TG、视觉、家电。

### 6.1 Home Server 接口

先实现：

```http
GET /robot/status
```

返回示例：

```json
{
  "online": true,
  "message": "Home Server connected"
}
```

### 6.2 firmware MCP 工具

新增工具：

```text
self.home.get_status
```

工具行为：

```text
读取 CONFIG_HOME_SERVER_URL
-> HTTP GET /robot/status
-> 返回 Home Server 的 JSON 给小智
```

### 6.3 小智 Agent 提示词

在小智 Agent 的角色设定或提示词里加入：

```text
当用户询问机器人状态、家庭服务状态、远程服务是否在线时，调用 self.home.get_status。
```

### 6.4 验收标准

用户说：

```text
查询一下家庭服务状态
```

期望链路：

```text
小智识别语音
-> 调用 self.home.get_status
-> 机器人请求 Home Server
-> Home Server 返回状态
-> 小智语音回答状态
```

如果这一步成功，说明核心链路已经打通。

## 7. 第二阶段：接 Telegram

第二阶段再接 Telegram，不急着做自然语言，先做明确命令。

推荐命令：

```text
/ping
/status
/say <text>
/photo
/light <room> on
/light <room> off
```

### 7.1 推荐通信方式

早期建议使用轮询，不先做 WebSocket。

链路：

```text
Telegram
-> Home Server 保存命令
-> firmware 定时请求 /robot/pending-command
-> firmware 执行命令
-> firmware POST /robot/command-result
-> Home Server 回复 Telegram
```

优点：

- firmware 实现简单。
- 不需要维护长连接。
- 对家庭网络更友好。

缺点：

- 有 2-5 秒延迟。

### 7.2 Home Server 接口

建议先设计：

```http
GET /robot/pending-command
POST /robot/command-result
GET /robot/status
```

待执行命令示例：

```json
{
  "id": "cmd_001",
  "type": "say",
  "payload": {
    "text": "我快到家了"
  }
}
```

执行结果示例：

```json
{
  "id": "cmd_001",
  "success": true,
  "message": "spoken"
}
```

## 8. 第三阶段：家电控制

家电控制统一放在 Home Server，不直接把米家、Home Assistant、红外协议等逻辑塞进 firmware。

Home Server 接口：

```http
POST /home/device/control
```

请求示例：

```json
{
  "device": "living_room_light",
  "action": "on"
}
```

firmware 新增 MCP：

```text
self.home.control_device
```

参数：

```text
device
action
```

两种入口共用同一套能力：

```text
语音 -> 小智 -> MCP -> Home Server -> 家电
TG -> Home Server -> 家电
```

## 9. 第四阶段：视觉问答

视觉由 Home Server 调视觉模型，firmware 负责拍照和上传。

Home Server 接口：

```http
POST /vision/explain
```

请求形式：

```text
multipart/form-data
question=<用户问题>
file=camera.jpg
```

firmware 新增 MCP：

```text
self.vision.describe_scene
```

参数：

```text
question
```

执行链路：

```text
小智调用 self.vision.describe_scene
-> firmware 获取 camera
-> camera->SetExplainUrl(...)
-> camera->Capture()
-> camera->Explain(question)
-> Home Server 调视觉模型
-> 返回识别结果
-> 小智说出来
```

注意：

```text
StackChanCamera::Explain() 调用前必须先设置 explain URL
```

否则会报：

```text
Image explain URL or token is not set
```

## 10. 第五阶段：长任务

录 10 秒视频、上传文件、发送 Telegram 这类任务不要用同步 MCP 硬等。

推荐设计成异步任务：

```text
self.camera.record_video_to_chat
```

立即返回：

```json
{
  "accepted": true,
  "task_id": "video_001",
  "message": "开始录制，完成后会发送到 Telegram"
}
```

后台执行：

```text
录制视频
-> 上传 Home Server
-> Home Server 发送 Telegram
-> 更新任务状态
```

配套工具：

```text
self.task.get_status
self.task.cancel
```

查询返回示例：

```json
{
  "task_id": "video_001",
  "status": "sent",
  "target": "telegram"
}
```

## 11. 推荐实施顺序

严格按下面顺序推进：

```text
1. 拉取 firmware 依赖
2. 确认 ESP-IDF 环境能 build
3. 新建 Home Server，提供 /robot/status
4. firmware 新增 CONFIG_HOME_SERVER_URL
5. firmware 新增 self.home.get_status
6. 在小智 Agent 提示词里声明状态查询工具
7. 语音测试状态查询
8. Home Server 接 Telegram /status
9. firmware 增加轮询远程命令
10. TG 实现 /say
11. TG 实现 /photo
12. 接一个最简单家电设备
13. 新增 self.home.control_device
14. 新增 /vision/explain
15. 新增 self.vision.describe_scene
16. 最后再做视频和异步任务
```

短期不要优先做：

```text
自建完整 xiaozhi-esp32-server
替换官方小智语音服务
```

这些都可以后置。

## 13. 最小验收闭环

第一版只验收这一件事：

```text
用户对机器人说：“查询一下家庭服务状态”
机器人通过 MCP 调用 Home Server
Home Server 返回状态
机器人用小智语音回答结果
```

这个闭环成功后，后面的 Telegram、家电、拍照、视觉，都只是继续扩展 Home Server 接口和 firmware MCP 工具。

## 14. 风险点

### 14.1 依赖未拉取

当前 firmware 依赖需要通过 `fetch_repos.py` 拉取。没有 `xiaozhi-esp32` 目录时，不能直接完整 build。

### 14.2 ESP-IDF 环境

如果 shell 里没有 `idf.py`，需要先配置 ESP-IDF v5.5.4。

### 14.3 Home Server 地址

Home Server 地址应使用独立配置，不要混用 `CONFIG_STACKCHAN_SERVER_URL`。

### 14.4 小智不一定主动调用工具

MCP 工具注册后，小智能看到工具，但是否调用还取决于：

- 工具名是否清晰。
- 工具描述是否准确。
- Agent 提示词是否明确。
- 用户表达是否能触发该工具。

所以新增工具时，工具说明要写清楚它适合什么场景、不适合什么场景。

### 14.5 长任务超时

录像、上传、复杂视觉分析不要同步等待。应设计成异步任务，MCP 只负责创建任务并返回 `task_id`。

## 15. 最终方向

最终系统应演进成：

```text
本地语音入口：
用户 -> 官方小智 -> MCP -> firmware -> Home Server -> 外部能力

远程消息入口：
用户 -> Telegram -> Home Server -> firmware / 家电 / 视觉模型
```

这条路线可以保留官方小智的语音体验，同时避免被 `xiaozhi.secret_key`、完整自建小智服务端、管理后台缺失等问题卡住。
